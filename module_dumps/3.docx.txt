[P1] (Title) PayGate - Secure Digital Payment Platform
[P2] (Normal) Modules: Payment Initiation & My Wallet
[P3] (Normal) SYNOPSIS
[P4] (Body Text) The PayGate (Transiq) platform is a production-grade payment gateway system developed for secure online monetary transfers and wallet bank account management. This document presents the design, architecture, database models, and test reports for Payment Initiation and My Wallet.
[P6] (Body Text) Built using React, FastAPI, and MongoDB Community Server, the system manages fund transfers through a deterministic Finite State Machine (CREATED -> VALIDATED -> AWAITING_PIN -> SUCCESSFUL / FAILED). Payments generate a unique background Transaction ID (TXN-YYYYMMDD-XXXXXX) allowing idempotent retries. Security PINs are encrypted via SHA-256 digests. My Wallet enables a two-step bank account linking workflow using 6-digit OTPs with 5-minute TTL expiration and attempt rate limiting.
[P8] (Heading 1) OBJECTIVE
[P9] (List Paragraph) Secure Payment Initiation: Multi-step guided payment workflow with background Transaction ID creation (TXN-YYYYMMDD-XXXXXX).
[P10] (List Paragraph) Beneficiary Validation: Verification of transfer recipient existence within the database.
[P11] (List Paragraph) Account Validation: Validation of funding account active status and verified flag (isVerified == True).
[P12] (List Paragraph) Pre-Flight & Commit Balance Check: Ensuring transfer amount > 0 and <= available balance at pre-flight and commit boundaries.
[P13] (List Paragraph) Security PIN Authorization: Six-digit PIN verification using SHA-256 cryptographic digest matching.
[P14] (List Paragraph) JWT Authentication: Enforcing JWT bearer token authorization across protected endpoints.
[P15] (List Paragraph) State Machine Execution: Modeling transaction lifecycles using FSM state transitions persisted in MongoDB.
[P16] (List Paragraph) Idempotent Retry: Retrying failed payments using the exact same Transaction ID.
[P17] (List Paragraph) OTP Account Linking: Two-factor bank account connection via 6-digit OTP with 5-minute TTL and 3-attempt cap.
[P18] (List Paragraph) Multi-Collection Balance Sync: Real-time balance synchronization across funding, connected, and core bank collections.
[P19] (List Paragraph) Standardized Error Handling: Standardized HTTP responses for frontend error toast notifications.
[P21] (Heading 1) SCOPE
[P22] (List Paragraph) Payment Initiation Scope: Background TXN creation, WALLET/IMPS/NEFT/RTGS payment methods, beneficiary & account validation, SHA-256 PIN check, failure recording, payment retries retaining same TXN ID.
[P23] (List Paragraph) My Wallet Scope: Display connected bank accounts, dummy_bank_accounts lookup, 6-digit OTP generation with 5-min TTL, attempt rate limiting, upsert=True bank linking, sub-wallet splits.
[P24] (List Paragraph) Out of Scope: Direct commercial bank API clearing networks, physical SMS gateway delivery (simulated locally), credit card acquiring networks.
[P26] (Heading 1) PROJECT DESCRIPTION & FUNCTIONAL MODULES
[P27] (Body Text) The system follows a three-tier architecture: React single-page frontend, FastAPI Python backend, and MongoDB database layer. Payment execution transitions through CREATED, VALIDATED, AWAITING_PIN, and SUCCESSFUL / FAILED states.

[P40] (List Paragraph) connected_bank_accounts: User verified bank accounts (id, accountNumber [Indexed], maskedAccountNumber, name, balance, isVerified, status).

[P45] (List Paragraph) wallets: Sub-wallet balance splits (accountId, name, allocatedAmount, updatedAt).

[P156] (Heading 1) CONCLUSION
[P157] (Normal) The implementation of the Payment Initiation and My Wallet modules for the PayGate (Transiq) platform successfully fulfills the technical and security requirements of a modern digital payment gateway.
[P159] (Body Text) By modeling payment execution as a deterministic Finite State Machine, the system enforces rigorous state transitions (CREATED -> VALIDATED -> AWAITING_PIN -> SUCCESSFUL / FAILED), ensuring transaction auditability and preventing ghost payments. Cryptographic security is achieved through SHA-256 digest hashing of Security PINs. The My Wallet module establishes a 2-step bank account linking flow governed by 6-digit OTPs with 5-minute TTL expiration and 3-attempt limits.
[P161] (Body Text) Data persistence using MongoDB Community Server leverages projection rules ({'_id': 0}), upsert semantics (upsert=True), and multi-collection balance synchronization to ensure absolute ledger consistency.
[P163] (Heading 1) FURTHER ENHANCEMENTS
[P164] (Body Text) Multi-document MongoDB transactions (session.start_transaction()), HTTP Idempotency-Key header support, immutable append-only ledger, Open Banking OAuth2 tokenization, machine learning fraud detection models, and production TLS/Vault security.
